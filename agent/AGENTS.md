# Agent Instructions (Botpress ADK Agent)

Botpress ADK project (`@botpress/runtime`). Owns RAG over the Canadian charity corpus and exposes the `searchCharities` workflow that Express proxies to. Bot dev server on **3000**, console on **3001**.

> Read `[.cursor/rules/botpress-adk.mdc](../.cursor/rules/botpress-adk.mdc)` first — it is the authoritative ADK conventions guide (one primitive per file, Zod schemas, channel-pinned conversations, `adk.zai` for typed LLM calls, etc.).

## Module map

```
agent/
├── agent.config.ts            # integrations (webchat 0.3.0), defaultModels (openai:gpt-4o-mini), secrets, state
├── agent.json / agent.local.json   # workspace + per-dev override (.local is gitignored)
├── data/
│   ├── charities/<id>.md      # GENERATED — KB source; one passage per file (see scripts/AGENTS.md)
│   ├── charities.indexed.json # GENERATED snapshot
│   └── charities.metadata.json# GENERATED — Express reads this to hydrate charityIds
├── scripts/sync-secrets.ts    # backend/.env → adk secret:set (runs before `npm run dev`)
└── src/
    ├── conversations/webchat.ts        # webchat.channel handler; exposes searchCharities as a tool
    ├── knowledge/charities.ts          # Knowledge over agent/data/charities/*.md
    ├── workflows/searchCharities.ts    # KB.search → per-result adk.zai.text rationale
    └── types/search.ts                 # Zod request/response (mirrored in backend/src/types/search.ts)
```

## Workflow contract: `searchCharities`

- **Input** (`SearchRequestZ`): `{ answers: { causes, beneficiaries, geography, givingStyle }, prompt, userId? }`.
- **Output** (`SearchResponseZ`): `{ queryId, results: [{ charityId, organizationName, score, rationale }] }`.
- Internals: `buildQuery()` flattens answers + prompt into one natural-language string → `Charities.search(query, { limit: TOP_K=5 })` → dedupes by `charityId` (parsed from passage `metadata.path` basename) → `adk.zai.text(...)` produces a one-sentence rationale per hit. Score is `1 - rank/N`.
- Trigger from CLI: `adk workflows run searchCharities '<json>' --wait --format json` (this is exactly what `backend/src/bot/client.ts` does).

## Local dev

```bash
cd agent
npm install
npm run dev           # runs secrets:sync, then `adk dev` (bot :3000, console :3001)
adk kb sync --dev     # AFTER editing agent/data/charities/*.md (regenerated by ingest)
adk chat              # REPL against the dev server
```

Schema/contract changes require an `adk dev` restart (workflow signatures are picked up at boot).

## Secrets

- Declared in `agent.config.ts` (`OPENAI_API_KEY`).
- **Single source of truth: `backend/.env`.** `agent/scripts/sync-secrets.ts` reads it and shells out to `adk secret:set` for each key listed in `ADK_SECRETS` (default: `OPENAI_API_KEY`).
- `npm run dev` invokes `secrets:sync` first, so the chat surface and the workflow always share the same key.

## Tests / evals

- ADK evals (`*.eval.ts` next to source) are planned (see `docs/architecture.md` Testing table). Run with `adk evals`.
- Backend integration tests stub the bot client — they do not exercise this workspace.
- For end-to-end smoke against the real workflow: `bash scripts/test-rag-pathway.sh --with-agent --skip-tests` (requires `adk dev` already running and `OPENAI_API_KEY` exported).

## Anti-patterns (in addition to those in `.cursor/rules/botpress-adk.mdc`)

- Editing `agent/data/charities/*.md`, `charities.indexed.json`, or `charities.metadata.json` by hand — they are **regenerated** by `scripts/ingest-charities.ts`. Edit `data/charities.seed.json` (or the CRA TSV) and re-ingest.
- Forgetting `adk kb sync --dev` after the markdown corpus changes — searches will return stale results.
- Running `adk secret:set OPENAI_API_KEY ...` by hand — diverges from `backend/.env`. Update `.env` and run `npm run secrets:sync` instead.
- Adding a workflow without a Zod `input`/`output` schema, or referencing it from Express without mirroring the types into `backend/src/types/`.
- Calling raw OpenAI / `fetch()` from inside the workflow. Use `adk.zai.text` / `adk.zai.extract` so the model is configured centrally in `agent.config.ts`.
- Pinning `channel: "*"` in `conversations/webchat.ts` — keep `webchat.channel` for type safety.
- Running `adk deploy` without explicit user confirmation.
